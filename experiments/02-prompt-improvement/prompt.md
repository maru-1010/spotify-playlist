# 頼んだ文面（after）

4回とも、`<対象ファイル>` と `<使う技法>` のところだけを置き換えて、同じ文面で頼みました。

```text
# 役割
あなたは、ソフトウェアテストの技法に詳しいテストエンジニアです。

# 背景
このリポジトリは、Spotifyのプレイリストを作る、個人開発のWebアプリです（画面＝React・TypeScript・Vite、サーバー＝Node.js・Express）。
テストの道具は入れてあります（画面側＝Vitest・jsdom・Testing Library、サーバー側＝Vitest・supertest）。

# 依頼
<対象ファイル> のテストを書いてください。
1. テストケースは <使う技法> で洗い出してください
2. よくあるケースだけでなく、極端な値や境目も確かめてください
3. 仕様が決まっていない点があれば、テストを書く前に質問するか、最終報告に「仕様の確認が要る」として挙げてください
4. 今の動きが本来の動きと食い違って見えるときは、今の動きを正としてテストで固めず、最終報告で指摘してください

# 守ること
・テストはVitestで書き、npm test で実行できるようにしてください
・外部への通信はモックにしてください
・対象のコードは変えないでください（テストのためにどうしても必要な最小限の変更は可。変えたら理由を書いてください）
・コミットはしないでください

# 最終報告
最後にテストを実行し、結果を次の順で教えてください。
1. <使う技法> で洗い出した内容（表や一覧で）
2. テストの件数と結果（成功・失敗）
3. 仕様の確認が要る点
4. 今の動きが本来の動きと食い違って見える点
5. 対象のコードを変えたか（変えたなら、その理由）
```

## この文面にした理由

- 実験①（before）の文面の条件（[../01-ai-test-generation/prompt.md](../01-ai-test-generation/prompt.md)）は、そのまま残しました。最後の「テストを実行し、結果を教えてください」は「最終報告」の節に移し、報告の順番を足しました
- CT-GenAI（ISTQB の生成AIとテストのシラバス）の2章にある、プロンプトの組み立て方（役割・コンテキスト・指示・入力データ・制約・出力形式）に沿って並べました
- 実験①で漏れた3つ（極端な値・境目／仕様が決まっていないところ／今の動きを正としてしまう）に効く指示と、対象ごとに使う技法の名指しを足しました
- 観点表は渡していません。渡すと「頼み方の工夫」ではなく「答えを写す」実験になるためです
- AIから質問が来たときに返す答えを、4回分そろえて決めておきました（「仕様は決まっていません。決まっていない点は最終報告に『仕様の確認が要る』として挙げ、テストは書ける範囲で書いてください」）。今回は、どの回も質問がなかったので使っていません
